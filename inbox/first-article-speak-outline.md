# Grok Bot 文章口述提纲：当前版

更新日期：2026-10-10。与 [骨架](first-article-skeleton.md) 的六章、25 个二级章节对应。事实查 [调研底稿](grok-bot-research.md)，详尽展开查 [大纲 v4](first-article-outline-v4.md)。

口述时先讲自己的经历；事实提示用于提醒，不必逐条照读。示例句不是本人经历，空缺处直接说“这里待补”，不临时猜数据。一次可录 15–20 分钟，也可以按章分段；时长仅供安排，不限制案例展开。

## 开场：先说一个真实结果（约 1 分钟）

开口提示：“我开始关注 Grok Bot，是因为我想让它帮我处理……目前做到……最直观的感受是……”

补任务、产物和第一感受。若有日报，展示一页即可，完整过程留到案例章。不要预设已经稳定自动发布。

## 1. 它是什么（约 2 分钟）

开口提示：“我先说清楚，它在我这里怎样接活、怎样把结果交回来。”

- **1.1 一句话定义：** 我怎么交代目标、资料和工具；它执行什么；我检查什么。随后解释个人智能体。
- **1.2 三个层次：** 模型提供判断，Bot 是持续职责，云电脑是工作环境。展示自己看到的浏览器、文件或终端；多个 Bot 共享同账号电脑。
- **1.3 连续例子：** 以日报为例，把交代、收集、成稿、核对、下一次复用串起来；这里只解释流程。

过渡：“理解这个工作方式之后，我再讲它为什么对我有用。”

## 2. 为什么用（约 3 分钟）

开口提示：“这些能力里，真正影响我工作方式的是……”按实际感受讲，没用过的注明官方支持。

- **2.1 持续工作现场：** 什么文件、登录或工作进度被保留？关闭本地电脑后有没有实际观察？自己的配置是什么，不泛称人人高配。
- **2.2 多设备：** 在哪些设备查看或继续任务？讲一个接力动作。官方支持 iOS 与 Android，本人未测不要自称已测。
- **2.3 分工协作：** 我建了哪些角色，为什么分开？有没有一次交接、重复或冲突？共享电脑不按角色隔离权限。
- **2.4 应用接入：** 选一个真的连接过的工具，说明授权、实际读取或写入。只装了插件就如实说到安装。
- **2.5 方法与定时：** 哪个任务先做过一次，怎样改成方法，是否建立 Routine，实际执行几次？解释 Skill 是方法，Routine 是触发。
- **2.6 邮箱：** 若用过，讲一封真实邮件怎样进入工作；未用过就简述官方能力。收到邮件不会自行唤醒，需要 Routine。

过渡：“这些能力最好用一个小任务验证，下面讲我是怎么开始的。”

## 3. 怎样上手（约 3 分钟）

开口提示：“我采用的是……路径，当时的套餐、设备和版本是……”

- **3.1 权益：** 我原来有什么订阅，是否用试用或账号关联？只详讲自己的路径。关联权益不叠加，不能随意迁移。
- **3.2 付款：** 从哪个入口、选哪档、月付还是年付、币种、付款方式、实付多少钱？支付宝没出现时只讲实际处理，不保证 CNY 或清缓存是通用修复。
- **3.3 下载与登录：** 官方下载入口、安装、账号、时区、遇到的提示。旧隐私模式与旧计费分别讲，不把所有老用户一概而论。
- **3.4 创建角色：** 首个 Bot 名称与职责；负责什么、用什么资料、交付什么、何时找我。
- **3.5 第一次交付：** 原话怎么派任务，接了哪些工具，它交回什么，我怎样验收？未跑通先说卡在哪。

可用首次任务示例（未实测）：整理指定时间范围内某个 AI 产品的 5 条动态，逐条保留日期、原始链接、摘要，保存文件。检查链接、日期、原文支持和文件后再考虑 Routine。

过渡：“上手以后，我把它放到几个实际场景里试了试。”若还未试，应改为“接下来我准备验证这些场景”。

## 4. 我的案例（约 5–7 分钟，优先展开）

开口提示：“我先讲最能说明整个过程的一个案例。”

- **4.1 日报：** 原来如何做 → 为什么交给它 → 原始任务 → 来源和工具 → 初稿问题 → 怎样纠正 → 最终文件 → 做了几次 → 人工与额度消耗。说清收集、成稿、审核、发布各到哪一步。
- **4.2 X 运营：** 究竟是找帖子、分析、选题、写稿、发帖还是复盘？挑实际做过的一环，展示输入和结果，说明人工参与。没有发布与效果记录不补结论。
- **4.3 云电脑作为代理出口：** 用户已确认这是独立云端环境的一个扩展场景。说链路：我的设备 → 我的实际连接方案 → Bot 云电脑 → 目标服务。用什么软件、连通到哪一步、解决了什么问题、什么情况下中断？官方经本地网络转发是相反方向，不当作这套方案的按钮。也可补真实脚本、文件处理用途。

每个案例都说“目前完成到哪里”。没有时间或用量记录就说未记录。失败和返工本身可以成为有价值的内容。

过渡：“这些场景有用，但也让我看到了持续使用的成本和限制。”

## 5. 踩坑与判断（约 3 分钟）

开口提示：“我真正遇到的问题是……它影响了……我采取了……目前……”

- **5.1 额度：** 哪档套餐、哪种任务、几次运行、用量如何变化？是否开启按需费用？解释周用量、步骤与 tokens，不拿聊天次数或编辑器月额度代算。
- **5.2 网络与登录：** 卡在本地登录、云电脑网站、插件调用还是最终结果？当时什么网络和开关，处理后任务是否完成？
- **5.3 维护：** 软件更新、重建或恢复对本人安装的软件、脚本、代理配置有什么影响？没有遇到则说明官方已提示的条件。
- **5.4 模型与结果：** 当前不能手动切换或确认每次模型。讲一次需要自己核对、返工或接手的事情；角色不代表权限隔离。
- **5.5 个人判断：** 接下来继续交什么任务？什么暂时留给自己？依据收益、消耗与介入程度，不预设“必买”结论。

收尾提示：“我会继续让它处理……，接下来最想验证的是……”

## 6. 附录（可录完正文后单独补）

- **6.1 更新：** 哪个已确认的版本变化影响本人使用？以官方 changelog 为准，标日期；无须把所有更新口述一遍。
- **6.2 术语：** 哪些英文词需要简短中文解释？Bot、云电脑、插件、Skill、Routine、周用量、按需。
- **6.3 入口：** 官方链接由调研底稿整理；付款和配置截图标本人日期、套餐与环境。

## 录完后的材料核对

补套餐与付款记录、配置截图、日报指令和产物、X 完成环节、代理实际链路、额度变化、运行次数及未解决问题。随后按章节整理文字，删重复解释，保留真实细节；精简分享贴等长文成立后再做。
